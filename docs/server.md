# Web server and HTTP API

`npm start` serves a small Fastify API on port 8080, or on `PORT` when it is set (`npm run dev` restarts on changes). Audits are stored in a SQLite file, `database.db`, in the working directory. Behind a proxy, set `PUBLIC_URL` to the address people reach the server at, such as `https://audit.example.com`, so the links in the web pages use it rather than the address the proxy forwards to.

| Route                | Does                                                                                                       |
| -------------------- | ---------------------------------------------------------------------------------------------------------- |
| `POST /audits`       | Queues an audit of the page in `{ "url": "..." }` and answers `202` with `{ id, status }` and a `Location` |
| `GET /audits/:id`    | Returns an audit with its `status`, `error` and `result`, `404` if it is unknown                           |
| `DELETE /audits/:id` | Deletes an audit from the database with `204`, `404` if it is unknown or already deleted                   |

A background worker runs queued audits one at a time. An audit's `status` goes from `queued` to `running`, then to `completed` with the results in `result`, or to `failed` with the reason in `error`, for example `Could not fetch page`. Poll `GET /audits/:id` until it is one of the last two. `result` is the JSON report of the one page, the same shape `--json` writes (`schema/report.schema.json`) with no `coverage`. Its `site` holds the site checks that mean something for one page: `canonical-elsewhere`, the response header checks, the checks of the origin's `robots.txt` (`blocked-by-robots`, `ai-search-blocked`, `robots-txt-failed`, `robots-txt-unreachable`) and `no-sitemap-declared`, and `origins` how that `robots.txt` treats AI crawlers. The link check and the sitemap checks do not run: one would request every linked page, the others need a sitemap. `robots.txt` is fetched under the same rules as the page, so with private destinations off, one on or redirected to a private address is not read and the audit reports `robots-txt-failed`. A result an earlier version stored, as the internal page or before these checks ran, is returned with an empty `site` and no `origins`. An audit that was running when the server stopped is queued again at startup, and fails after three interrupted attempts. An audit whose result cannot be saved, such as when the disk is full, fails with `Audit result could not be saved` rather than staying `running`. Deleting an audit removes it from `database.db`, with SQLite's `secure_delete` on so its address and results do not linger in the file. An audit deleted while it runs still finishes, but nothing of it is saved. Audits that an earlier version only hid when they were deleted are removed at startup.

`POST /audits` answers `400` for a URL it cannot audit, including a private network address, a host that does not resolve or an address longer than 2048 characters, counted as sent and once percent-encoded, and `503` when DNS fails for a reason that may pass on retry. The web form refuses the same addresses. Every error answers `{ "error": "..." }`.

**Sites on your own machine.** Set `ALLOW_PRIVATE_DESTINATIONS=1` to audit private addresses too, such as a development site on `localhost:3000`, `127.0.0.1` or another machine on your network, the way the CLI can. It is off by default because a server others can reach would let them use it to reach your network. Only set it on a server you run for yourself, which `npm start` is: it listens on `localhost`. The server logs a warning at startup when it is set.

**Host names it answers to.** The server answers only requests whose `Host` is `localhost` or a name under `.localhost`, an IP address, such as `127.0.0.1` or `[::1]`, or the host of `PUBLIC_URL`, whatever the port. Any other host gets `421 Misdirected Request` from the API and the pages: a page for a browser that asks for one, `{ "error": "..." }` for every other client. Only the stylesheet and script under `/assets/` load at any host, so that page has its style; they hold nothing about anyone's audits. The `Host` header is read as the client sent it, never `X-Forwarded-Host`, which a script can set to anything. This stops DNS rebinding, where a site you visit points its own name at your machine so its scripts can use the server as if it were their own, to queue audits of your network and read the results. Behind a proxy that forwards its own host name, set `PUBLIC_URL` to the address people use.

The same server has web pages for people, which check one page at a time through the same queue:

| Page                     | Does                                                                                                        |
| ------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `GET /`                  | The check form. An address without a scheme is checked over `https://`, or `http://` for localhost or an IP |
| `POST /check`            | Queues the address and redirects to its page, or shows the form again with what is wrong (`400`, `503`)     |
| `GET /check/:id`         | Progress while the check runs, then the results: what to fix, the search result preview and the page facts  |
| `GET /check/:id.md`      | The results as Markdown for Claude, `409` while the check runs                                              |
| `GET /check/:id/delete`  | Asks before deleting, for browsers that run no script                                                       |
| `POST /check/:id/delete` | Deletes the results and redirects to `/?deleted`, `404` when there are none                                 |

**Results in Claude.** The results page has a Copy for Claude button that puts the results on the clipboard as Markdown, to paste into Claude Desktop or Claude Code: the verdict, each finding with why it matters, how to fix it and up to 10 places it occurs, the page facts and the address of the full JSON. The same text is under "What gets copied" on the page and at `/check/:id.md`, so in Claude Code you can say "read http://localhost:8080/check/<id>.md and fix these on my site". Text from the checked page is set in code spans, apart from what pageaudit wrote. Browsers only allow the clipboard on `https:` and `localhost`; elsewhere the button says Copy failed and selects the text instead.

The pages work without JavaScript: a check in progress reloads itself every few seconds and Delete results opens a page that asks first. `src/web/public/checker.js` polls `GET /audits/:id` instead, checks the address field as it is typed, copies the results for Claude (the button is hidden without it) and asks before deleting in a dialog. Pages answer with a Content-Security-Policy that allows only their own stylesheet and script, and the forms that change state take a post only from this site: `Sec-Fetch-Site: same-origin`, or in a browser too old to send it, an `Origin` of this server. An unknown path answers a browser with a page and every other client with `{ "error": "Not found" }`.
